3분RAG 코드

런북 임베딩 검색 + 확신 없으면 기존 경로로

// agent/rag/classifier.py
if not self.enabled:            → keyword
if index is None:            → keyword
vector = embedder.embed([text])[0]     # [질문][시스템][상태][알림]
top1, top2 = index.search(vector)
if top1 < min_score:      → keyword  (0.50)
if top1-top2 < min_margin: → keyword  (0.03)
return top1                    # rag
  • agent/rag/embedder.py — Ollama qwen3-embedding:0.6b
  • agent/rag/index.py — 10문서 인덱스 + JSON 캐시
  • 선택 근거는 /health·metadata·SSE로 노출
실제 SSE 출력 — classifier_source=rag, rag_score=0.6452, rag_margin=0.2177
RAG — agent/rag/{embedder,index,classifier}.py · 연결 지점 agent/graph.py::_select_incident_type()5
3분MCP 코드

MCP로 모니터링·런북을 조회하고, 데이터 선택은 한 곳에서

# mcp_server.py (ops 서버)
@mcp.tool
def get_monitoring_status(system_name) → SystemStatus
@mcp.resource
def get_incident_runbook(incident_type) → str
@mcp.prompt
def incident_analysis_prompt(system_name, symptom)
# agent/data_profile.py
DATA_PROFILE=base|extended
→ 파일 선택의 단일 결정 지점 (하드코딩 5곳 제거)
  • agent/mcp_client.py — stdio subprocess로 ops 서버 연결, find_resource_template로 런북 URI 탐색
  • mcp_server_docs.py는 decoy — 의도대로 쓰지 않는다
  • 파일 선택이 5곳에 흩어져 있으면 시스템만 늘고 조사 대상은 6개로 잘린다 → 한 곳으로 모았다

의존성 주입: SupervisorDeps에 rag을 넣고 lifespan에서 1회 생성 → 노드가 os.environ을 직접 읽지 않는다.

LangSmith: 노드에 @traceable 적용, .env로 트레이싱 켜짐 — 실 API 키 없는 환경이라 캡처는 미수행
