3분MCP 코드

조회는 MCP로, 데이터 선택은 한 곳에서

# mcp_server.py — ops 서버
@mcp.tool     get_monitoring_status(system_name)
@mcp.resource get_incident_runbook(incident_type)
@mcp.prompt   incident_analysis_prompt(system, symptom)

# agent/data_profile.py — 파일 선택의 단일 지점
DATA_PROFILE = base | extended   # 6시스템 | 12시스템

경로가 다섯 곳에 흩어져 있으면 시스템만 늘고 실제로 조사하는 대상은 여섯 개로 잘린다 — 이름만 늘고 조사는 그대로인 "가짜 확장"이 된다.

  • Tool / Resource / Prompt 를 구분해 쓴다 모니터링 조회 · 런북 본문 · 분석 절차
  • stdio subprocess 로 붙는다 agent/mcp_client.py — list → find → read 순서로 탐색
  • decoy 서버는 쓰지 않는다 mcp_server_docs.py — 쓰지 않음이 설계 의도
  • RAG는 의존성 주입 SupervisorDeps.rag — 노드가 환경변수를 직접 읽지 않는다
  • LangSmith 트레이싱 경로 확보 노드에 @traceable — 실 API 키 없는 환경이라 캡처는 못 했다
